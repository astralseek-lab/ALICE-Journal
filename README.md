## 复核方法

整树：CI 在每次 push 时复算全部哈希与清单外文件，红即阻断。
单件（无需任何工具）：对任一下载到的文件算 sha256，与本仓
[`publish_manifest.json`](publish_manifest.json) 里该路径的 `sha256` 逐字符比对即可，
例如 `sha256sum 00_规范/素材/AstralSeek_Lab_logo.png`。

## 本仓收录什么

规范（顶层文件、两份风格规范、QA 脚本）+ 已发布单元的机器面
（文章、图、证据链 JSON、L1 产物、复现记录、复现任务书、反例）。

投影时做过路径归一化（发布件里的本机绝对路径改占位符，读者照抄才不至于断）：
受控树根 -> ${JOURNAL_ROOT}（1 处）；旧批次工作区绝对路径 -> <旧批次工作区>（2 处）。归一化只动路径写法，不动数字与结论。

## 本仓明确不收录什么

| 未公开件 | 理由 |
| --- | --- |
| 决策记录、批次记录 | 内部运营台账（含预算与工单流转） |
| 原 SOP v4.2.0 | 内部作业手册（系统代理、盘符与解释器绝对路径），已由顶层文件取代 |
| 单元生产记录、QC 记录 | 内部工序记录；读者需要的复现细节已进 `reproduction_log.md` |
| 候选池 | 未定选题，公开即等于预告 |
| 出版社 PDF / 全文 XML | 可按 DOI 与原刊获取，不在本仓再分发 |
| 挂起稿 | 未通过发布闸的稿件不出现 |
| 投影工具本身 | 工具不是证据；投影证据以 `publish_manifest.json` 的可复算性为准 |

未公开不等于不可核：凡影响结论的细节，均已在公开件的「局限与边界」节写明，
指向的事实不依赖内部台账成立。
